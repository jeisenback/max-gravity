# Parts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fitted parts with a source (yard, used with a quirk, printed) for the ship's five systems; a repair scene in port where Hester picks and the hand argues; the hand's fight wearing and reading fire control and shields; two station slots of gun parts the hand buys and keeps.

**Architecture:** A new `js/parts.js` (loaded after `wear.js`) holds the tables and the pure functions (state in, value out). `wear.js` reads a fitted part's wear factor; `fightui.js` applies wear and the parts' fight numbers at the edge of the fight (`fight.js` stays pure); the repair scene is offered on `landed` beside the hull repair (`repairs.js`); the station counter is a section on the Port page.

**Tech Stack:** vanilla JS classic scripts, canvas; tests are node:test, browser tests through `tests/helpers.js` `open()`, node tests through `tests/nodecontext.js`.

**Spec:** `docs/superpowers/specs/2026-11-13-parts-design.md` (#1135).

## Global Constraints

- Every new top-level name unique across the scripts; `js/parts.js` linked in `index.html` after `js/wear.js` (`tests/globals.test.js`).
- Nothing new on `G` (`tests/gfields.test.js`); new state lives on the save: `st.parts` (the ship's), `h.station` and `h.partsAt` (the hand's record).
- New logic takes the state it reads and returns a value; the caller reads `G`. Runs under `tests/nodecontext.js`.
- Page markup on the view helpers (`js/views.js`, the `h` template).
- An owner-only or hand-only thing is a gate at its edge (`role()`, `hired()`, `chapterOf`), never a fork inside.
- No dice of the game's in the repair: used parts by `hash` of port and day; the captain's pick a fixed score. The seeded pins (`tests/*pin.test.js`) must not move; if one does, the plan is wrong.
- No emojis. Words to `docs/bible/voice.md`.
- `npm test` before every push; `npm run soak` in Task 7.

## Review Focus

- An old save with no `st.parts` and no `h.station`: wears, repairs and fights exactly as today until a part is fitted. Test in Task 1 and Task 6.
- A fund too thin for even the printed part: no scene that landing, and no error. Test in Task 4.
- A reload in the middle of a stay: the repair is offered once a stay, not again (`h.partsAt`). Test in Task 4.
- The Wear setting at Off: nothing wears, so no repair ever comes up; a printed part's 1.75 is times zero. Test in Task 1.
- The ship changing hands (`signOn` into the co-op, the owner's buy): `st.parts` goes with the old ship, `h.station` goes with the hand. Test in Task 1 and Task 6.

### Task 2: Used parts and their quirks

**Files:**
- Modify: `js/parts.js`, `js/wear.js` (`perf`), `js/hired.js:99` (`handCheck` adds `partEdge`)
- Test: `tests/parts.test.js`

**Interfaces:**
- Produces:
  - `PART_QUIRKS`: an array of `{ id, system, from, plus, minus }`, three per system, fifteen in all. `plus` and `minus` are each one effect: `{ wear: k }`, `{ perf: k }` (capped so `perf` is at most 1.05), `{ fight: { dmgMult: k } | { shields: k } }`, or `{ edge: { post: n } }`. `from` is a line in the voice, for example `'a feed off a Compact patrol cutter'`.
  - `usedPartAt(st, portId, day, sys) -> quirk | null`: `null` on about half the days at a port with an outfitter, by `hash(`${portId}|${day}`)`. Always a quirk at `hygiea` (the Boneyard) and Phobos Yards. The quirk is picked from that system's three by `hash(`${portId}|${day}|${sys}`)`.
  - `quirkEffect(st, kind) -> number`: the product (or for `edge`, the sum) of the fitted parts' effects of a kind. `partEdge(st, kind)` is `quirkEffect` of `edge`.
- Consumes: Task 1's `fittedPart`.

  - Always a quirk at `hygiea`. `null` at a port with no outfitter.
  - A fitted quirk with `{ wear: 0.8 }` makes `partWear` 0.8 for yard, or 1.4 for printed.
  - `{ edge: { post: 0.05 } }` raises `handCheck('gunnery', 1, 'post')` by 0.05.
