# Traits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A record of counts on the hired hand, eight traits earned from it, each seen on the hand's page, said once when it lands, and opening a door or turning a reading somewhere a body meets the ship.

**Architecture:** `js/traits.js` is a pure module (the record's writer, the trait table, the derived list) that runs in plain Node. `js/hired.js` gains `recordHand(key)`, the one call every site makes, which writes the count and queues the moment. The doors are marked choices added where each scene builds its list; the readings are one line at a knob that exists. Words live in the text layer under `scene:traits`.

**Tech Stack:** Vanilla JS classic scripts, `tests/nodecontext.js` for node tests, Playwright browser tests through `tests/helpers.js open()`, goldens (`UPDATE_GOLDEN=1`), pins (`PIN_WRITE=1`), the text-layer check (`tests/scenelines.test.js` over `tests/sceneplay.js`).

**Spec:** `docs/superpowers/specs/2026-11-10-traits-design.md`

## Global Constraints

- CLAUDE.md: read and write `.claude/heartbeat.json`; no emojis; desktop only; classic scripts with unique top-level names, every script linked in `index.html` and in `editor.js` SCRIPTS; new logic takes `st` (or `h`) as parameters; something only an owner does is a gate at the edge, never a fork inside (`js/role.js`); markup on the `h` helpers with a golden.
- `TRAITS` is taken (the crew's personalities): the table is `HAND_TRAITS`, the lines `scene:traits`.
- A key absent from `h.record` reads as zero; nothing is migrated; a trait is earned once and kept for the run.
- No trait adds to the roll.
- Words are first drafts in the register of `docs/bible/voice.md`; every new line is played by `tests/sceneplay.js` so `tests/scenelines.test.js` passes.
- Commits end with the session's attribution lines; the headless shell suite runs before the push.

## Review Focus

1. A save from before, with no `record` and no `traitsTold`: every site's `recordHand` call counts from zero, `handTraits` answers `[]`, and nothing throws (Task 1 tests `handTraits({})`, Task 2 tests a site on a hand with no record).
2. An owner (no hand): every site still runs; `recordHand` returns with no hand, and no door or reading appears (Task 2 and Task 4 test the owner's contact and bar).
3. The moment lands mid-fight or mid-dialog: `traitNote` must not open a dialog over a fight panel; in a burn it is a message, at a port a note (Task 2 tests a trait earned by `repelSettle` with the panel open: the message is in the comms, no dialog replaced).
4. The speaker of a moment is dead, ashore or hurt: the captain says it; Jonah says nothing and is still marked told (Task 2 tests both).
5. Reliable's count resets on a late delivery, so a late one after five on time does not earn it and the next five do (Task 1 tests the reset).
